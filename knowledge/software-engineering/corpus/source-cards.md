# Software Engineering Classics Knowledge Base Source Cards

This seed corpus contains source metadata, selection notes, and routing guidance. It is intentionally not a substitute for copyrighted books. Public-web/open-license texts can be ingested into this corpus; copyrighted books remain metadata-only until the user supplies a lawful copy for private indexing.

## Abstraction and Programming Fundamentals

Structure and Interpretation of Computer Programs by Harold Abelson, Gerald Jay Sussman, and Julie Sussman is the canonical source for abstraction, interpretation, metalinguistic abstraction, procedures as data, data as procedures, streams, interpreters, and building complex software through layered language design. Use it when questions concern program structure, abstraction barriers, interpreters, symbolic computation, or functional programming.

## Large-Scale Software Engineering Practice

Software Engineering at Google by Titus Winters, Tom Manshreck, Hyrum Wright, and contributors is the preferred source for sustainable codebase practices at scale: code health, testing culture, code review, style guides, build systems, dependency management, deprecation, migration, API stewardship, and engineering culture. Use it when questions concern long-lived code, large repositories, maintainability at organizational scale, or engineering process.

## Production Reliability and Operations

Site Reliability Engineering: How Google Runs Production Systems is the preferred source for service reliability, SLOs, toil, monitoring, alerting, incident response, postmortems, release engineering, capacity, overload, cascading failures, distributed consensus, and operational practices. Use it when questions concern production systems, on-call, reliability engineering, observability, or running distributed systems.

Release It! by Michael T. Nygard is metadata-only until supplied by the user. It is a key source for production resilience patterns, stability antipatterns, circuit breakers, bulkheads, timeouts, integration points, and real-world production failure modes.

## Architecture and Systems Design

The Architecture of Open Source Applications is a case-study source for concrete architecture decisions in real systems. Use it when questions call for examples of how actual open-source projects structure components, manage tradeoffs, or solve design constraints.

Designing Data-Intensive Applications by Martin Kleppmann is metadata-only until supplied by the user. It is the key modern reference for storage engines, replication, partitioning, transactions, distributed systems, consistency, batch processing, stream processing, and data-system tradeoffs.

Patterns of Enterprise Application Architecture by Martin Fowler is metadata-only until supplied by the user. Use its metadata as a pointer for enterprise layering, data mappers, repositories, transaction scripts, domain models, gateways, and application architecture patterns.

Design Patterns: Elements of Reusable Object-Oriented Software is metadata-only until supplied by the user. It is the classic reference for reusable object-oriented design patterns including factories, strategy, observer, composite, decorator, adapter, command, state, visitor, and template method.

Domain-Driven Design by Eric Evans is metadata-only until supplied by the user. It is the major source for ubiquitous language, bounded contexts, aggregates, entities, value objects, repositories, domain services, and strategic design.

## Code Quality, Refactoring, and Legacy Systems

Refactoring by Martin Fowler is metadata-only until supplied by the user. It is the key source for improving internal design without changing external behavior, identifying code smells, and applying small behavior-preserving transformations.

Working Effectively with Legacy Code by Michael Feathers is metadata-only until supplied by the user. It is the key source for characterization tests, seams, dependency breaking, and safely modifying code without tests.

Code Complete by Steve McConnell is metadata-only until supplied by the user. It is a broad construction reference for implementation quality, defensive programming, variable naming, routines, control flow, debugging, and code-level design.

Clean Code by Robert C. Martin is metadata-only until supplied by the user. It is a commonly cited source for readability, naming, functions, comments, error handling, unit tests, and code craftsmanship. Treat it as one perspective among several, and prefer concrete project conventions when they conflict.

A Philosophy of Software Design by John Ousterhout is metadata-only until supplied by the user. It is a modern source for managing complexity through deep modules, narrow interfaces, information hiding, and tactical versus strategic programming.

## Delivery, DevOps, and Team Performance

The Twelve-Factor App by Adam Wiggins is a public web source for SaaS application design: one codebase, explicit dependencies, config in environment, backing services, build-release-run separation, stateless processes, port binding, concurrency, disposability, dev/prod parity, logs as streams, and one-off admin processes.

Continuous Delivery by Jez Humble and David Farley is metadata-only until supplied by the user. It is the classic reference for deployment pipelines, build automation, reliable releases, testing strategy, and release management.

Accelerate by Nicole Forsgren, Jez Humble, and Gene Kim is metadata-only until supplied by the user. It is the source for delivery performance research, DORA metrics, deployment frequency, lead time, change failure rate, MTTR, culture, and technical practices associated with high-performing organizations.

Peopleware by Tom DeMarco and Tim Lister is metadata-only until supplied by the user. It is a classic source for teams, productivity, workplace environment, management, hiring, and human factors in software delivery.

The Pragmatic Programmer by Andrew Hunt and David Thomas is metadata-only until supplied by the user. It is a broad software craft source for responsibility, orthogonality, automation, tracer bullets, prototypes, debugging, requirements, and professional habits.

The Mythical Man-Month by Frederick P. Brooks Jr. is metadata-only until supplied by the user. It is the classic source for schedule estimation, Brooks's Law, conceptual integrity, communication overhead, and software project management.

## Software Design Philosophy and Complexity

Out of the Tar Pit by Ben Moseley and Peter Marks is a public-web paper pointer; extracted text should not be committed until redistribution rights are verified. It is a useful source for essential versus accidental complexity, mutable state as a source of complexity, control complexity, code volume, and functional-relational programming ideas.

Worse Is Better by Richard P. Gabriel is a public author-hosted essay pointer. It is useful for design philosophy, simplicity versus completeness, implementation pragmatism, Unix/C design culture, and adoption dynamics.

Test-Driven Development: By Example by Kent Beck is metadata-only until supplied by the user. It is a foundational source for red-green-refactor, triangulation, tests as design pressure, xUnit patterns, and incremental implementation.
